# SharePoint Diff 1.2.0

## Tiếng Việt

Bản tối ưu data và đọc/ghi cho Windows x64, C# WPF/.NET 10. Giữ ba chế độ ghi đè, hai lượt tải, kiểm tra bản sao lưu/tệp cài và giao diện Việt–Anh.

- JSON được nén; tách hẳn luồng nội dung để giữ đúng byte và tải tiếp bằng Range.
- Kiểm kê theo thay đổi từ drive và list item, gắn tài khoản/site/thư viện; có lựa chọn đọc lại đầy đủ, không quét đầy đủ theo lịch.
- Dùng hash đã lưu khi nhận dạng NTFS khớp, hiện nguồn hash và ngày tính; kiểm tra dần khi máy rảnh, có thể dừng.
- Duyệt cây thư mục một lần, giảm lượt hash và kiểm tra nguồn lặp; dùng lại bản trên máy/cache/sao lưu, gom dự toán theo nội dung.
- Sơ đồ cột lưu theo SHA-256; manifest ghi theo đợt sau nhật ký hoàn tất bền. Giữ bản cũ trước chuyển định dạng và phục hồi từ mọi lượt chạy liên quan.
- Khi có đổi đường dẫn lúc thay tệp, giữ bản bị thay thực tế để xem xét. Thống kê có cả đọc/ghi, yêu cầu API và lượng nội dung đã đọc khi tải.

**Kiểm chứng:** 179 kiểm thử tự động và bốn lượt kiểm tra giao diện/lỗi đạt. Sáu ca cưỡng bức kết thúc tiến trình đã thử trên tệp riêng. JSON kiểm kê lưu sẵn 2.472 tệp giảm khoảng 84,7% dung lượng lưu, giữ kiểu dữ liệu. Xem `docs/Verification.md` để biết số đo và giới hạn.

**Đã thử site thật với lõi bản mới:** đối chiếu đầy đủ/delta/đầy đủ trên thư viện 1 tệp, 3 thư mục khớp cả metadata giữ kiểu JSON. Lượt delta khi không đổi dùng 4 yêu cầu API, không gọi `/items` và không đọc lại nội dung hai tệp local có hash đã lưu. Tải, ghi đè có sao lưu và dùng lại cache/local tải tổng cộng 40 byte nội dung. Đăng nhập chỉ giữ trong bộ nhớ; không ghi SharePoint. Mã ứng dụng/lõi giữ nguyên bản RC1, dùng chương trình kiểm thử riêng để thử mạng thật; executable WPF được kiểm tra giao diện cách ly.

Chưa thử các thay đổi trên SharePoint thật, mất điện thật, đăng nhập lại Windows, FAT/SMB thật hoặc chuyển DPI vật lý nhiều màn hình. Các ca nguồn đổi và lỗi có chủ đích được thử bằng giả lập.

Cần .NET 10 Windows Desktop Runtime. Giữ toàn bộ thư mục `_SPDiff` khi sao lưu/chuyển máy, đặc biệt `schemas/`, manifest, nhật ký và các bản sao lưu. Nên thử ghi đè trên bản sao thư mục trước khi dùng cho tài liệu đang làm việc.

## English

Optimizes network and logical disk I/O while preserving verified backups, staged-file readback, post-install verification, the three overwrite modes and the two-transfer limit.

Includes compressed JSON with separate raw content transport, account-bound drive/list delta cursors, NTFS identity-based scan hashes, bounded idle block checks, directory indexing, shared versioned schemas, durable commit journals and batched manifest checkpoints. The UI exposes full local/remote checks, saved-hash provenance, observation dates and I/O counters in Vietnamese and English.

**Validation:** 179 automated tests and four isolated UI/fatal smoke runs pass, including six forced-process termination boundaries. A private saved 2,472-file inventory uses about 84.7% less serialized storage including schemas. These are application I/O/storage measurements, not physical SSD endurance or total internet traffic.

**New live tests passed:** the unchanged full/delta/full inventories agree on a one-file, three-folder library. The delta pass makes four API requests, no `/items` request and no content reads for two local hash-cache hits. Download, verified-backup replacement and cache/local reuse download 40 payload bytes total. The test program uses the unchanged RC1 application core; the packaged WPF executable is tested separately in isolated demo mode. Authentication remains in memory and no SharePoint writes occur. Remote mutations, physical power/network loss, actual Windows sign-in, real FAT/SMB and physical multi-monitor DPI transitions remain unverified on the live environment; injected failures and remote changes use simulated tests.

Requires .NET 10 Windows Desktop Runtime. Keep the entire `_SPDiff` tree when moving metadata; try overwrites on a copy first.
